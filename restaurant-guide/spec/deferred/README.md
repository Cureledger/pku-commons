# Deferred: the judgment layer

`pdas-v0.1-DEFERRED.md` and its implementation scored menus against a
phenylalanine budget (percent-of-daily-allowance thresholds, a 0-4 Menu Fit
rung, a composite tier). **That layer is deferred and is not in use.**

Reason: the suitability scale is Nina's to define, and defining it before the
raw menu data exists gets the order backwards. A threshold invented ahead of
the corpus will quietly determine what the corpus appears to say.

What is live instead: `../menu-census-v0.1.md` — observable, countable menu
facts with no diet judgment applied. Census first, scale second.

Nothing here is cited, displayed, or imported by the app. It is kept only so
the argument for splitting Menu Fit from Accommodation is not lost: that part
survives review and should inform whatever scale replaces it. The A axis
(what the kitchen will do, verifiable only by contact, expiring after 180 days)
is unaffected by this deferral and stays in the live schema.
